# Status note — M7.2.1 context composition (October 2026)

**Status:** dated progress note. It reports design and verification work,
not experimental results. Earlier documents in this repository, including the
pre-registered [Model Ecology Observatory](model-ecology-observatory.md)
design, are unchanged. This note adds to them; it does not revise them.

## Summary

Since the September snapshot, the private runtime has been working toward
milestone **M7.2.1**: adding *context composition* as a first-class,
identity-bearing variable in the observatory, and doing it without giving any
context component authority over state.

M7.2.1 is an **implementation candidate, not a release**. An independent
review returned NO-GO on the first candidate, and the remaining findings are
being closed in a fixed order before any experiment runs.

## What changed in the design

### 1. Context configuration is split from context behavior

The observatory now records context in two separate places:

| Record | When | Holds |
|---|---|---|
| Context configuration | before the run | which components, in which order, with a configuration hash |
| Context runtime summary | after the run | visible-token trajectory, fold/recall/fallback behavior, provenance status |

Composition order is part of the identity: the same components in a different
order count as a different treatment. Runtime behavior is never treated as
treatment identity, and nothing observed during a run may be used as a
pre-run routing feature for that same run. Records written under the earlier
schema stay as they are; the new fields are additive and are never
back-filled into old evidence.

### 2. Active-context virtualization enters as an observed component

The runtime adds active-context virtualization (folding and recalling parts
of a long conversation so the model sees a bounded working set) as a
candidate context component. It is integrated as **observation only**:

- it may decide what the model sees;
- it does not decide what is true;
- it has no routing, memory, execution, or state authority.

The component is a fork of the open-source
[context-warp-drive](https://github.com/dogtorjonah/context-warp-drive)
project, pinned to a reviewed commit.

### 3. Provenance supplied by a component is not trusted

The first independent review found that a context component could report its
own provenance as "verified" and have that accepted. The fix generalizes:

- trust-bearing fields can't be set by the thing being observed;
- the host checks the component against its own pinned identity;
- a match yields *host-bound, unattested*, never *verified*;
- trust violations are recorded as a distinct provenance-rejection status,
  separate from ordinary missing telemetry.

The general rule is the same one that governs model output: **the subject
does not certify its own authority boundary.**

### 4. Git-history isolation is not a sandbox

Benchmark chambers were built to hide future Git history from the model under
test. Review found that this is evidence hygiene, not confinement: the worker
still ran as an ordinary host process with host filesystem, environment,
credential, and network reach. A benchmark run is now meant to be
**comparison-eligible only if confinement is verified by the host**, and to
fail closed otherwise. Diagnostic runs may still execute, but they are
structurally ineligible as comparison evidence. This work is in progress.

### 5. Model identity is observed, not assumed

A provider may serve a request under a model name that now points to a
different model. The observatory therefore treats the requested model name as
a claim and the provider-reported model as the observation. Runs are
comparable only within one observed model identity, and a provider-side remap
during an experiment invalidates that run set rather than silently
contaminating it.

## Remaining order of work

```text
benchmark confinement
-> context-component dependency integrity
-> controlled vs diagnostic evidence tiers
-> publication and import boundaries
-> pinned dependencies reachable and reconciled
-> full verification
-> first controlled experiment (one variable: baseline compressor vs fold-only)
-> final independent review
```

The first experiment changes exactly one context component. Token savings
alone will not promote it; it must also show no regression in correctness,
provenance, security, or isolation.

## Status

No experimental results exist yet. The hypotheses in the observatory design,
including the interaction between context strategy and model identity, remain
untested.
